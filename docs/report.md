# GLaDOS Robot — Отчёт о состоянии системы

**Дата:** 2026-03-25
**Ветка:** feature/remote-ollama
**Конфигурация:** qwen3:14b (remote GPU), Whisper medium (local CPU), FastVLM (local CPU)

---

## 1. ASR (распознавание речи)

**Модуль:** `src/glados/ASR/whisper_asr.py`
**Модель:** faster-whisper `medium` (769M), CPU, int8

### Проблемы

- **Скорость:** Warmup ~9с, инференс ~2-3с на CPU. Ощутимая задержка между окончанием речи и появлением текста.
- **Качество на разговорном русском:** Ошибки на сленге, быстрой речи, нечёткой дикции. Примеры из логов:
  - "пасел на донеса" вместо реальной фразы
  - "математическое уравнение снизит" — полный бред
  - "АС-40 сломалось" — непонятно, было ли это сказано
- **Галлюцинации на тишине:** Whisper генерирует фантомный текст когда ничего не говорят. VAD фильтр помогает, но не на 100%.
- **GIL bottleneck:** CTranslate2 держит GIL во время инференса, что ранее вызывало deadlock с asyncio.to_thread (исправлено — warmup теперь синхронный).

### Варианты улучшения

| Вариант | Качество | Скорость | Сложность |
|---------|----------|----------|-----------|
| Whisper `large-v3` на CPU | Лучше | ~15с/inference — неприемлемо | Низкая |
| Whisper на GPU сервере | Отличное | <1с | Средняя (нужен API endpoint) |
| Vosk (офлайн) | Среднее | Быстро | Низкая |
| Deepgram/Google API | Отличное | <0.5с | Низкая (но платное/облачное) |

**Рекомендация:** Вынести Whisper `large-v3` на GPU сервер через HTTP API (faster-whisper-server). Та же архитектура что с LLM.

## 2. Компьютерное зрение

### 2.1 VLM (описание сцены)

**Модуль:** `src/glados/vision/fastvlm.py`
**Модель:** FastVLM (ONNX, CPU)

#### Проблемы

- **Только английский язык.** Описания приходят на English ("young man with short hair wearing robe"), LLM вынуждена переводить в голове, что тратит контекст и вносит путаницу.
- **Слишком общие описания.** Каждый кадр: "man with short hair in gray robe seated in office chair". Не замечает действия, предметы, изменения.
- **Низкий лимит токенов.** `max_tokens: 64` — недостаточно для деталей.
- **CPU inference.** Медленно, ~2с на кадр.

#### Варианты улучшения

| Вариант | Язык | Качество | Скорость |
|---------|------|----------|----------|
| qwen2.5-vl:7b через Ollama API | Русский | Отличное | ~3с на GPU |
| LLaVA 1.6 через Ollama API | Русский | Хорошее | ~2с на GPU |
| Оставить FastVLM + перевод в промпте | Английский | Среднее | Быстро (CPU) |

**Рекомендация:** Использовать `qwen2.5-vl:7b` (уже установлена на сервере). Поддерживает русский, гораздо умнее, детальнее описывает.

### 2.2 FaceID (распознавание лиц)

**Модуль:** `src/glados/robot/face_id.py`
**Модель:** InsightFace SCRFD (det_10g.onnx) + ArcFace

#### Проблемы

- **Нестабильное распознавание.** В логах run17 ни одного "Лица: Создатель" — 18 фото в базе, но face_results часто пустой или все `unknown`.
- **Жёсткий threshold.** Порог совпадения может быть слишком строгим для webcam-качества (640x480, плохое освещение, ракурсы).
- **Нет логирования similarity scores.** Непонятно, распознаёт ли модель лицо с низким score или не находит лицо вообще.
- **Одна средняя эмбеддинг.** 18 фото усредняются в один вектор — теряется вариативность ракурсов.

#### Варианты улучшения

- Снизить similarity threshold (с текущего значения до 0.3-0.4)
- Хранить несколько эмбеддингов (кластеры ракурсов) вместо одного среднего
- Добавить логирование similarity scores для отладки
- Рассмотреть MediaPipe Face (быстрее, стабильнее на webcam)

## 3. LLM (генерация ответов)

**Модуль:** `src/glados/robot/brain_async.py`, `src/glados/robot/llm_client.py`
**Модель:** qwen3:14b, remote GPU (Tailscale), num_ctx 4096

### Проблемы

- **TTFT 7-12с.** Ощутимая пауза перед первым словом. При росте контекста может увеличиваться до 20+с.
- **Thinking overhead.** qwen3 генерирует скрытый `<think>` блок перед каждым ответом (~50% токенов). ThinkFilter стрипит его, но GPU время и TTFT уже потрачены.
- **Ответы слишком длинные.** Промпт просит "1-2 предложения", но модель часто генерирует 3-4 предложения.
- **Emotion tags нестабильны.** Иногда модель забывает ставить `[SARCASM]` и т.д., или ставит emoji вместо тега.

### Варианты улучшения

- **Отключить thinking:** `/no_think` в промпте или параметр `enable_thinking: false` → TTFT -50%
- **Жёсткий промпт:** "Максимум одно предложение. Не более 15 слов."
- **num_predict: 100** — хардкодный лимит длины ответа в Ollama options
- **Prefill cache:** Ollama кэширует промпт, повторные запросы с тем же prefix быстрее

## 4. FaceDisplay (UI)

**Модуль:** `src/glados/robot/face_display.py`
**Рендер:** pygame, unified window

### Проблемы

- **Перезагрузка ассетов при каждом resize.** В логах `_load_all` вызывается 5+ раз подряд при старте (VIDEORESIZE события от pygame). Каждый раз загружает 10 PNG файлов.
- **Нет кэширования.** При ресайзе грузит файлы с диска заново, хотя достаточно масштабировать уже загруженные.

### Фикс

- Кэшировать оригинальные surfaces, при ресайзе масштабировать из кэша
- Добавить debounce на VIDEORESIZE (игнорировать серию событий, ждать стабилизации)

## 5. Аудио (TTS + playback)

**Модуль:** `src/glados/robot/voice.py`, `src/glados/audio_io/sounddevice_io.py`
**TTS:** glados_ru (VITS), **Playback:** sounddevice

### Проблемы

- **Хрип/артефакты.** При быстрой смене аудио-чанков `sd.stop()` + `sd.play()` может вызывать щелчки и хрип на PipeWire.
- **Нет echo cancellation.** GLaDOS слышит собственную речь через микрофон → ASR распознаёт её ответы → может вызвать цикл. Текущий workaround: `speaking_event` подавляет ASR во время воспроизведения, но это грубое решение.
- **TTS качество.** VITS модель glados_ru звучит роботизированно (что в данном случае плюс), но иногда проглатывает слоги.

### Варианты улучшения

- PulseAudio AEC (Acoustic Echo Cancellation) модуль
- Crossfade между аудио-чанками (20-50мс) вместо hard cut
- Исследовать XTTS v2 для более качественного TTS (но медленнее)

---

## 6. Архитектурные проблемы

- **Нет retry/fallback для remote LLM.** Если сервер недоступен — GLaDOS зависает навсегда. Нужен timeout + fallback на локальную модель.
- **VisionWorker не утилизирует GPU сервер.** VLM и FaceID работают на CPU ноутбука, хотя GPU сервер доступен.
- **Нет метрик.** Нет замера end-to-end latency (речь пользователя → начало TTS playback). Невозможно отслеживать деградацию.
